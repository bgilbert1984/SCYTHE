# LibIQ (arXiv 2505.10537v3): reading notes and adoption plan

Status: non-normative. Nothing here changes a protocol, declaration or evidence rule.

Source: Olimpieri, Giustini, Lacava, D'Oro, Melodia, Cuomo, "LibIQ: Toward Real-Time Spectrum
Classification in O-RAN dApps", MedComNet 2025 (arXiv 2505.10537v3, 11 Dec 2025). Six pages, read in
full from the local PDF (`docs/*.pdf` is gitignored and not committed). Numbers below are as reported;
none were reproduced. Code: `github.com/wineslab/lib-iq` (license not checked).

## What the paper does

- C++ library with Python bindings: parse I/Q binaries, FFT/PSD, spectrograms, dataset builders, CNN classifier.
- Runs inside an O-RAN dApp beside a gNB. Input is post-FFT frequency-domain samples from unscheduled
  OFDM symbols, sensed about every 8 ms (1,536 samples per vector, 1-15 vectors per window).
- Energy Peak Detector: take the maximum-energy peak in a window and keep 600 samples around it, so the
  classifier does not depend on the interferer's centre frequency.
- Classifier: 3 x (Conv1D 64 + BatchNorm + ReLU), global average pooling, FC, 6-way softmax. Four features
  per sample: real, imaginary, magnitude, phase.
- Data: about 35,200 series, six classes (LTE, jammer, no RFI, square, triangular, radar = sine) from
  signal generators, GNU Radio and SCOPE; one gNB at 3.6192 GHz / 40 MHz; four interferer centre
  frequencies, two for training and two held out; 1 MHz sample rate; Colosseum emulator plus one OTA testbed.
- Reported: accuracy 0.971-0.987, per-prediction latency 0.90-2.23 ms (budget 10 ms).

## Limits that matter here

- Closed set: every window is forced into one of six classes. No rejection, no discovery.
  A strong CW tone would be labelled "Radar" regardless of its origin, including a receiver artifact.
- Narrow evaluation: same hardware and generators; only the interferer centre frequency is held out.
  No cross-site or cross-receiver result. Weakest class is LTE (0.791 +/- 0.132), seen only in the emulator.
- Inconsistencies in the text: Table II lists F1 = 0.972 for the 5-vector window while precision 0.988 and
  recall 0.987 imply about 0.987; the table shows per-prediction latency falling with window size while the
  text says it rises; real and imaginary parts are labelled (Q) and (I) respectively. Treat the latency
  and F1 figures as unverified.
- "Absence of overfitting" is asserted from aligned training/validation curves only.

## Adoption plan

Adopt as ideas, not as code:

1. Peak isolation before analysis: a fixed window around the strongest peak makes a detector independent of
   centre frequency. Candidate use: examine the persistent features found in the 2026-11 centre tests.
   Limit: the detector handles one peak per window, so overlapping emitters need a different treatment.
2. Per-decision latency as a reported quantity: state a budget, measure per-prediction time with mean and
   spread over repeated runs, and report it next to accuracy.

Do not adopt:

3. The closed-set classifier. Any classifier applied to our captures needs open-set rejection and must be
   evaluated against known receiver-side features (DC and low-frequency lines, impulsive noise) first.
4. O-RAN dApp integration: no gNB, no control loop.

Before any reuse of the code:

5. Check the repository license; confirm the input format (the paper describes frequency-domain samples
   while our files are u8 interleaved time-domain I/Q); reproduce any figure we rely on.

Constraints inherited from existing work: results from the XTR remain characterization only while its
reference oscillator is undeclared, and 8-bit byte statistics near the quantization floor tracked
distribution width, not emissions, so classifier inputs must be checked for that confound.
