# RF datasets we can replay using the Si5351 signal generator

> **Status:** proposal. The dataset descriptions below (WSPR.live, DeepSig, SigMF) were not independently verified. For the Experiment E keyed-source design, see `EXPERIMENT_E_BENCH_PLAN.md`, "Stage 1 keyed source".

The Si5351 is an excellent candidate for a low-cost, reproducible RF stimulus generator for SCYTHE, but it is not a full IQ waveform replay device.

After reviewing the PU2CLR/SI5351 repository, the distinction is important: we can replay datasets describing frequencies, carrier activity, hopping sequences, timing, and certain simple modulations, but we cannot directly feed recorded complex IQ samples into this hardware and reproduce the original waveform.

The project uses an Arduino to control three Si5351 clock outputs. Its documented configuration supports 32.768 kHz to 160 MHz, with selectable tuning steps from 1 Hz to 1 MHz.

For SCYTHE, this opens up a particularly interesting capability: converting an RF observation dataset into a repeatable physical experiment that our SDR receiver can measure and compare against the original evidence.

## Best datasets and experiments

| Dataset or signal type | Si5351 suitability | What SCYTHE could test |
|---|---|---|
| HF carrier occupancy and frequency logs | Excellent | Detection, frequency accuracy, dwell-time analysis |
| Slow frequency-hopping sequences | Excellent | Hop reconstruction, missing-event detection, emitter clustering |
| Multi-carrier beacon scenarios | Excellent | Three-emitter tracking and spectral separation |
| Slow FSK / frequency-shift events | Conditional | Symbol transitions, timing, frequency classification |
| WSPR / FT8 timing and frequency metadata | Partial | Scheduled carrier activity; not waveform-faithful decoding |
| Historical numbers-station frequency schedules | Partial | Activity schedules, frequency changes, synthetic transmission timelines |
| HF comb and interference datasets | Excellent | Harmonic classification, spurious-signal detection |
| ADS-B at 1090 MHz | Not directly | Outside Si5351's fundamental output range |
| AIS at 161.975 / 162.025 MHz | Not recommended | Outside the project's documented 160 MHz ceiling, with unsupported GMSK replay |
| Raw SigMF IQ captures | Not directly | Requires an IQ-capable transmitter for faithful replay |

The strongest initial experiment is HF frequency occupancy and hopping replay, because it uses the Si5351's actual strengths rather than attempting to turn a programmable oscillator into an arbitrary-waveform generator.

## 1. Real datasets worth starting with

- **WSPR.live historical spot dataset** (best real-world starting point). Billions of historical reception reports with timestamps, frequencies, signal-to-noise measurements, reported drift, and station identifiers. We can extract frequency/time events and recreate their carrier activity in a shielded test environment. These would be synthetic RF reconstructions, not authentic WSPR messages. Source: wspr.live.
- **Synthetic HF comb and oscillator-interference dataset** (best hardware characterization). Generate known carrier spacings, frequency sweeps, overlapping emitters, and on/off sequences. No third-party download necessary. This is especially suitable for distinguishing internally generated SDR artifacts from genuine signals reaching the receiver.
- **DeepSig RadioML 2016 / 2018** (best ML reference dataset). Contains labeled synthetic modulations and varying signal-to-noise ratios. Very useful for evaluating SCYTHE classification algorithms in software, but only simplified tone or frequency-transition features could be reconstructed with the Si5351. DeepSig explicitly cautions that these historical datasets have known issues.
- **SigMF recordings and metadata** (best standard for SCYTHE integration). SigMF preserves signal sample data alongside frequency, sample-rate, annotation, and capture metadata. An adapter could extract annotated carrier events for the Si5351 while preserving the original IQ recordings for software replay or an IQ-capable SDR transmitter. Source: sigmf.org.

An especially promising fifth option is a historical HF frequency-activity dataset assembled from public schedules and observations. For the Soviet numbers-station scenario we've been developing, SCYTHE could reconstruct when unidentified signals appeared, shifted frequency, disappeared, and reappeared. Those events are easy to reproduce as carrier behavior without broadcasting historical messages.

## 2. What an actual replay would look like

Illustrative three-output, time/frequency event replay (CLK0, CLK1, CLK2). Synthetic schedule, not a measured dataset or a claim of phase-continuous retuning.

The replay process would be:

1. **Historical RF dataset:** CSV, observation logs, SigMF annotations.
2. **SCYTHE event-replay compiler:** frequencies, clock channels, dwell durations, timing.
3. **Arduino + Si5351:** three independently configurable oscillator outputs.
4. **Attenuation + shielded or conducted test path:** Si5351 -> attenuator/filter -> SDR receiver.
5. **SCYTHE measurement and correlation:** actual captures vs. declared replay truth.

This would let us produce an unusually valuable kind of training evidence: an RF capture for which we also know the intended emitter frequency, on/off times, and source-channel identity.

## 3. First experiment: SCYTHE HF-3 synthetic dataset

I'd start with a small, deterministic dataset at approximately 7 MHz. These are synthetic test frequencies, not retransmissions of licensed or historical broadcasts.

Prototype event schedule (4-second sample, three clock outputs):

| Time | CLK0 | CLK1 | CLK2 |
|---|---|---|---|
| 0 s | 7.0400 MHz | 7.0500 MHz | 7.0600 MHz |
| 1 s | 7.0415 MHz | 7.0500 MHz | 7.0600 MHz |
| 2 s | 7.0380 MHz | 7.0500 MHz | 7.0620 MHz |
| 3 s | 7.0420 MHz | 7.0500 MHz | 7.0620 MHz |

We'd test whether SCYTHE correctly recognizes three simultaneously active sources, identifies CLK0's frequency changes, and associates CLK2's changes with the same source rather than inventing new emitters.

For a formal benchmark, I'd record the expected schedule and the measured capture separately, then compare frequency error, missed events, false detections, and timing jitter.

## 4. Hardware limitations worth designing around

The Si5351 outputs CMOS square waves, which contain harmonics. Its three outputs are not three arbitrary independent RF transmitters: they share internal clock resources, and some frequency combinations or changes can affect other outputs.

Also, Arduino I2C retuning has latency and jitter. The repository's 1 Hz tuning-step capability describes frequency selection, not a 1 Hz frequency-accuracy guarantee or a fast waveform sample rate.

That means our first test should use relatively slow transitions (hundreds of milliseconds to seconds), measure actual edge timing, and avoid interpreting oscillator spurs as signals from the dataset.

For the existing NESDR receiver, use a conducted connection through appropriate attenuation, filtering, and DC isolation where necessary. The Si5351's output level can exceed what the SDR input should receive directly. Avoid an antenna for initial experiments.

SCYTHE governance matters here too: the previously established Gate C preflight does not authorize Gate D RF replay. I'd keep dataset conversion, dry-run scheduling, and analysis in Phase 0. Connecting the generator and enabling its outputs should require a separate, bounded authorization under the appropriate hardware-control lifecycle.

## 5. Which path delivers the most value?

| Objective | Hardware approach |
|---|---|
| Benchmark frequency detection and event timing | Si5351 + existing receive SDR |
| Reproduce HF combs and simple synthetic emitters | Si5351 + filters/attenuation |
| Study authentic WSPR or FT8 decoding | Receive IQ capture or proper digital-mode signal generator |
| Replay recorded AM, FM, FSK, or PSK waveforms faithfully | IQ-capable SDR transmitter |
| Replay large RF datasets with repeatability | GNU Radio / SoapySDR + supported TX hardware |

My recommendation is to build a SCYTHE RF Replay Corpus containing paired original observations, deterministic stimulus schedules, conducted RF captures, measured uncertainty, and machine-readable ground-truth annotations.

Start with WSPR-derived carrier schedules and synthetic HF combs. These are comparatively easy to verify and valuable for the classifier and inference-rule work already underway.

Then use an IQ-capable SDR when we need faithful modulation replay, instead of asking the Si5351 to do something its architecture fundamentally doesn't support.

The commercial angle is promising: a modest-cost, auditable RF regression fixture for testing spectrum-analysis software, SDR front ends, and edge RF anomaly detectors.

The most interesting deliverable isn't the signal generator. It's the reproducible dataset-to-physical-RF benchmark that SCYTHE could own.
